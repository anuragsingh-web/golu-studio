# Pintu: rating a new idea or uploaded build (proposed 18 Nov 2026, discussed with Anurag)

Same pillars, weights, input rules and caps as SCORING_V2.md. An idea has no market data of its own, so momentum, staying power and size are borrowed from comparables.

1. Deconstruct: core mechanic, extra mechanics, core input type (tap_simple / tap_complex / drag / swipe / tap_double / drag_merge / tap_swipe / multi), meta, theme, monetisation. Play an HTML build if given; watch video; read images/docs.
2. Comparables: tag the idea like Sensor Tower Game IQ (sub-genre, theme, game tags/deep tags). Pick 3-5 closest live games. Momentum, staying power and size = their weighted median minus 1 point (their success isn't ours). Check crowding of the combination: proven-but-sparse = high clone-wave score; 200+ clones/yr = A3 capped at 5.
3. Judge design: hook clarity in 3 s + retry urge; input simplicity (Anurag's rules); mashup check if 2+ mechanics; monetisation fit; theme and live-ops; feasibility and twist.
4. Output scorecard: score + one-line reason per pillar, Overall (weighted average, caps applied), confidence, comparables used (with links), and the top 2-3 changes that would raise the score.

Confidence: low = text/mockup only; medium = playable HTML build or video; high = real test KPIs.
Test KPI targets when available (hybrid casual, from idea_rubric_research.md): ~35% D1, ~15% D7, US iOS CPI < $1. Publishers (Voodoo, SayGames, Kwalee) no longer treat these as hard pass/fail gates.
